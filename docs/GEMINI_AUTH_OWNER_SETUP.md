# Owner setup for Gemini Smart Report

Keep `AI_PUBLIC_ENABLED=false` and `AI_BETA_ENABLED=false` until account-side configuration is complete. Basic Report needs none of these settings. Do not enable billing, upgrade any plan, or send secret values through chat.

1. **Netlify**. Confirm `VHarshB/CommitCred` uses the Free plan and the intended production origin is `https://commitcred.netlify.app`. The canonical build should use the assigned Netlify URL. Keep preview deployments unconfigured for AI. Use regular local CI checks and batch any required Netlify production deploys.
2. **Supabase Free**. Create or select a Free project. Record the project URL and publishable key under **Project Settings → API Keys**. Make a server-only secret key. In **Authentication → URL Configuration**, set Site URL to `https://commitcred.netlify.app` and allow `https://commitcred.netlify.app/api/ai/callback`. Keep the redirect allowlist narrow. Use a separate project and explicit origin for a separate test site. Open the SQL Editor and run [the migration](../supabase/migrations/202611190001_smart_report_credits.sql) once, or use `supabase db push` after linking the correct project. Confirm RLS is enabled and only `service_role` can execute `public.cc_ai`.
3. **Google OAuth**. In **Supabase → Authentication → Sign In / Providers → Google**, copy the callback URL shown for this actual project. In **Google Cloud → Google Auth Platform**, configure Branding, Audience and the initial test users. Under **Clients**, create a **Web application**. Add `https://commitcred.netlify.app` as an authorized JavaScript origin and the exact copied Supabase callback as an authorized redirect URI. Enter the Google client ID and client secret in the Supabase Google provider settings. Enable that provider and **manual identity linking**. CommitCred requests `openid email profile`. Keep OAuth in testing until owner review is complete.
4. **Guest CAPTCHA**. Create a free Cloudflare Turnstile widget restricted to `commitcred.netlify.app`. Enter its secret in **Supabase → Authentication → Bot and Abuse Protection** and enable CAPTCHA. Enable anonymous sign-ins and set conservative Supabase Auth rate limits. The application sends the challenge token through the server-side Supabase signup. Confirm a missing, invalid, reused, or expired challenge cannot allocate a guest wallet before sharing an invite. Keep the Turnstile secret in Supabase only.
5. **Gemini free tier**. In Google AI Studio, verify that your project is on the unpaid tier with no billing account or paid API access. Verify the exact model supports structured JSON, what its current request/token quotas are, and the applicable regional and age terms. Choose a model such as an available Flash-Lite variant only after its free quota is confirmed in your project. Make a dedicated restricted API key and choose site limits at or below the verified limits. The default cap is an application limit. Google can impose lower limits.
6. **Netlify variables**. Set the following in **Project configuration → Environment variables** for the production deploy context. Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` for Builds and Functions. Set `SUPABASE_SECRET_KEY`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `TURNSTILE_SITE_KEY`, `AI_SECURITY_SECRET` and the AI flags/limits for Functions. Use a cryptographically random secret of at least 32 characters. Set `AI_ALLOWED_ORIGIN=https://commitcred.netlify.app` after verifying the address. Set `AI_FREE_TIER_CONFIRMED=true` only after verifying step 5. On plans without scoped variables, use production context values and keep the SDK calls confined to server routes. Do not put credentials in `netlify.toml`, a preview, or a `NEXT_PUBLIC_` secret.
7. **Private live verification**. Keep public AI off. Set `AI_BETA_ENABLED=true` and a strong random `AI_BETA_INVITE_CODE` of at least 24 characters. Share the code privately with an eligible adult tester in the United States. In Netlify, use Deploys → Trigger deploy to build the verified branch once. Check that the actual OpenNext function exposes trusted geo/IP context and declines missing/non-US context. Test consent and CAPTCHA, anonymous reports 3→2→1→0, a real Google link and +3 once, return sign-in, Google-first balance, known Google-link conflict, and sign-out. Generate with a public repo and inspect output and evidence links. In a controlled private test, exercise a provider failure and response retry, then inspect balances and attempt counters. Verify the production CSP with live Turnstile.
8. **Public decision**. The free Gemini terms restrict API clients directed toward or likely accessed by minors. A checkbox is self-attestation. Review the actual audience and deployment before considering public use. Keep AI in a private adult beta if the policy requirements cannot be met. Only after a compliant review, trusted US geo verification, free quota confirmation, and live checks, may the owner turn beta off and set both `AI_PUBLIC_ELIGIBILITY_VERIFIED=true` and `AI_PUBLIC_ENABLED=true`. Modes are mutually exclusive. This repository does not activate either.
9. **Pause and rollback**. Set both AI flags false and deploy to stop new authentication, reservations and Gemini calls. On Netlify, deploy environment changes require a deploy to take effect. For emergency disablement before a new deploy completes, revoke the dedicated Gemini API key in AI Studio. The Basic path stays independent. To roll back code, publish the previous known-good deploy or revert the feature commit. Retain the ledger to preserve lifetime allowances.
